# ADR 0008: 문서(Document)와 제품(UI) 타이포그래피 스케일의 분리

## Status

**Accepted**

## Context

Sonagi 디자인 시스템 V3의 컴포넌트(Button, Input, Badge, Modal 등)를 조립하고 검증하는 과정에서, 기존 피그마에 등록되어 있던 텍스트 스타일(`Body/Base 16px`, `Body/Small 13px` 등)과 실제 컴포넌트 뼈대 간의 심각한 규격 불일치(Mismatch)가 발견되었다.

기존에 세팅된 타이포그래피 스케일은 블로그 아티클이나 긴 텍스트 문서를 편안하게 읽기 위한 **'문서(Document) 최적화'** 스케일이었다. 그러나 UI 컴포넌트들은 한정된 버튼이나 배지 안에서 픽셀 단위의 정밀한 오토 레이아웃 밸런스를 유지해야 하므로, 글로벌 스탠다드인 **14px과 12px 기반의 조밀하고 단단한 '제품(UI) 최적화' 스케일**이 절대적으로 필요했다.

## Decision

우리는 타이포그래피 시스템을 두 개의 트랙으로 명확하게 분리(Decoupling)한다.

1. **Document Track (기존 유지)**: `Headings/*`, `Body/*`, `Caption`
   - 목적: 긴 글, 블로그, 아티클, 약관 등 가독성이 최우선인 곳에 사용.
   - 특징: 넉넉한 줄간격(Line Height), 편안한 크기(16px, 19px 등).

2. **UI Track (신규 신설)**: `UI/*`
   - 목적: 버튼, 인풋, 라벨, 뱃지, 모달 등 프로덕트 인터페이스 조립에 사용.
   - 특징: 콤팩트한 줄간격, 14px과 12px 중심의 조밀한 스케일.
   - **신설 목록 (총 6종)**:
     - `UI / Title 18` (18px Bold, LH 24): 모달/카드 제목
     - `UI / Body 16` (16px Medium, LH 24): 리스트 아이템 본문
     - `UI / Label 14` (14px Medium, LH 20): 버튼, 인풋 라벨, 탭
     - `UI / Body 14` (14px Regular, LH 20): 모달/카드 본문 텍스트
     - `UI / Label 12` (12px Medium, LH 16): 뱃지, 작은 캡션
     - `UI / Detail 12` (12px Regular, LH 16): 힌트 텍스트, 툴팁

## Consequences

- **Positive**: 컴포넌트를 조립할 때 텍스트 박스가 위아래로 쓸데없이 팽창하여 오토 레이아웃을 망가뜨리는 현상을 원천 차단한다. 디자이너와 프론트엔드 개발자는 용도(UI vs 문서)에 맞춰 망설임 없이 텍스트 스타일을 골라 쓸 수 있다.
- **Negative**: 피그마 텍스트 스타일 목록이 약간 길어질 수 있으나, 슬래시(`/`) 네이밍을 통해 카테고리가 완벽히 접히므로 관리상의 부담은 없다.
