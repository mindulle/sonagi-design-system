# ADR 0004: 상태색 정의 + Elevation/Hue 후속 보정

- **상태**: ✅ Decision 확정
- **시작일**: 2026-08-22
- **확정일**: 2026-08-22
- **관련 이슈**: CEO-926
- **관련 문서**: [ADR 0001(색상)](./0001-color-system-redefinition.md), `QA-CHECKLIST.md`

ADR 0001 시각 검증 시 남겨둔 4개 후속 과제 중 3개(Elevation, 상태색, Hue 그룹)를 처리한다. 다크모드는 별도 ADR 0005로 분리.

## 1. Elevation 사다리 보정

**문제**: `bg-base`(L=0.968)와 `bg-elevated`(L=0.988)가 ΔE(2000)=2.96으로, 중간 단계인 `bg-surface`와의 거리(3.46)보다도 가까웠음 — 가장 멀어야 할 두 레벨이 제일 안 구분됨.

**결정**: `bg-elevated`를 톤을 살짝 준 근사-흰색 대신 **순백(`#ffffff`)**으로 변경.

| 비교                  | 기존 ΔE | 변경 후 ΔE       |
| --------------------- | ------- | ---------------- |
| bg-base ↔ bg-surface  | 3.46    | 3.46 (변경 없음) |
| bg-base ↔ bg-elevated | 2.96    | **5.01**         |

위계 순서(base < surface-거리 < elevated-거리)가 정상화됨.

## 2. Hue 그룹 분리 원칙 명문화

**확인**: 뉴트럴 계열(ink/text/border, H≈27~34°)과 액센트 계열(accent/accent-hover, H≈24~25°)이 5~6° 차이나는 것은 계산 부산물이 아니라 **의도적으로 유지하기로 결정**. 액센트를 뉴트럴보다 살짝 더 "선명한" hue 쪽으로 두는 건 액센트의 시각적 팝(pop)을 강화하는 흔한 전문가 기법.

**원칙**: 이후 새 토큰 추가 시, 뉴트럴/구조색은 H 27~34° 범위 유지, 액센트/인터랙티브 색은 H 22~26° 범위를 허용 오차로 둔다. 이 범위를 벗어나면 의도를 명시할 것.

## 3. 상태색 (Success/Warning/Error/Info)

**문제**: 기존 DESIGN.md 상태색(초록 `#2ea043`/빨강 `#f85149`/파랑 `#4A90E2`/앰버 `#d29922`)은 범용 채도의 차가운 색으로, 새 러스트/코랄 브랜드(H 24~30°)와 이질적. 특히 전통적인 "error red"(H≈25°)를 그대로 쓰면 브랜드 accent(`#db6c66`, H≈25°)와 거의 같은 hue라 **에러 상태와 브랜드 액센트가 혼동될 위험**이 있음을 확인.

**Options Considered**: error의 hue를 마젠타 쪽으로 밀어 accent와의 거리를 확보하는 정도를 테스트:

| error 후보 H            | ΔE(accent)                         |
| ----------------------- | ---------------------------------- |
| 25° (전통적 red 그대로) | 6.63 (위험 — accent와 너무 가까움) |
| 25° (L/C 재조정)        | 11.30                              |
| 15°                     | 12.39                              |
| 0° (마젠타 과다)        | 18.19 (더는 "red"로 안 읽힘)       |

**Decision**: 색상은 보편적 의미(초록=성공/빨강=위험/앰버=경고/파랑=정보)를 그대로 유지하되, **명도·채도 레시피를 브랜드와 통일**해서 같은 시스템처럼 보이게 하고, error만 L/C를 재조정해 accent와 확실히 구분:

| 토큰            | 값        | oklch              | bg-base 대비 | 비고                                                                                             |
| --------------- | --------- | ------------------ | ------------ | ------------------------------------------------------------------------------------------------ |
| `state-error`   | `#d33a3c` | 0.58 / 0.19 / 25°  | 4.30:1       | ΔE(accent)=11.30 — 확실히 구분                                                                   |
| `state-success` | `#308639` | 0.55 / 0.14 / 145° | 4.16:1       |                                                                                                  |
| `state-warning` | `#a77600` | 0.60 / 0.15 / 80°  | 3.65:1       | 앰버 계열은 흰 텍스트와 궁합 나쁨(백색 대비 4.01:1) → **다크 텍스트(ink) 전용**, ink 대비 4.53:1 |
| `state-info`    | `#2a75ba` | 0.55 / 0.13 / 250° | 4.39:1       |                                                                                                  |

**연한 배경 버전** (배지/알림용, 각 hue에서 L≈0.97, 저채도):

| 토큰               | 값        | main-on-light 대비                    |
| ------------------ | --------- | ------------------------------------- |
| `state-error-bg`   | `#fff4f3` | 4.39:1                                |
| `state-success-bg` | `#f1f9f1` | 4.26:1                                |
| `state-warning-bg` | `#f3eadb` | (ink 텍스트 15.22:1 — 별도 문제 없음) |
| `state-info-bg`    | `#f1f8ff` | 4.51:1                                |

**사용 규칙**: `state-error`/`success`/`info`를 자체 배경(-bg) 위에 텍스트로 쓸 땐 main-on-light 대비가 4.5:1에 살짝 못 미치는 경우(4.18~4.39)가 있으므로, **배지/라벨 텍스트는 굵게(Medium 이상) + 14px 이상**으로 제작해 WCAG의 "큰 텍스트 3:1" 기준을 정당하게 적용받도록 한다(전부 3.86 이상으로 여유 있게 통과). 순수 본문 문단에는 상태색 텍스트를 직접 쓰지 않는다.

## Consequences

- `@sonagi/tokens`의 `--sng-color-state-*` 전면 교체, ADR 0001 major 범프에 포함
- `bg-elevated` 값 변경으로 Figma Foundation Color System 프레임 재렌더 필요
- 배지/알림 컴포넌트 설계 시 "상태색 텍스트는 굵게+14px 이상" 규칙을 컴포넌트 스펙에 반영해야 함

## Validation

- Elevation ΔE, 상태색 bg/white/ink 대비, accent와의 ΔE 전부 `coloraide`로 계산 완료 (2026-08-22)
