# ADR 0001: Procedural Graphics Pipeline — 목적, SSOT, 시각 규칙

- **Status:** Proposed
- **Date:** 2026-08-29
- **Scope:** `packages/graphics-generator` 한정. 코어 UI/토큰 ADR(`/decisions/0001~0010`)을 대체하거나 무효화하지 않는다.
- **Tracking:** CEO-1034

---

## 1. Context

### 1.1. 왜 필요한가 (실제 니즈)

디자인 시스템 개발 중 다음 니즈가 반복적으로 발생했다.

1. **아이콘**: `packages/icons`는 현재 `lucide-react`를 그대로 re-export 하는 껍데기다(`src/index.ts` 2줄). 즉 **Sonagi 고유 아이콘을 만들 수단이 없다.** 브랜드 전용 아이콘(소나기, 낙엽, 파문 등)이 필요할 때마다 외부 라이브러리에서 "비슷한 것"을 찾아 쓰는 타협이 반복된다.
2. **로고/심볼**: 고정된 래스터 파일로만 존재하여, 크기·테마(다크모드)·계절 변주마다 수동 재작업이 필요하다.
3. **키 비주얼/OG 이미지**: 블로그·배너·썸네일마다 배경 그래픽을 매번 손으로 만든다. 브랜드 일관성이 사람의 기억력에 의존한다.

### 1.2. 왜 생성형 AI가 답이 아닌가

이미지 생성 모델은 **재현 불가능(non-deterministic)** 하고, `stroke-width: 2px` 같은 **정확한 수치 제약을 지키지 못하며**, 벡터가 아닌 래스터를 뱉는다. 디자인 시스템의 핵심 요구사항(일관성·정확성·버전 관리 가능성)과 정면으로 충돌한다.

반면 절차적 생성(procedural generation)은 **같은 입력 → 같은 출력**을 보장하고, 토큰 한 줄을 바꾸면 전체 에셋이 규칙에 맞춰 일괄 갱신된다.

## 2. Decision

### 2.1. 목적 (Goals) — 이 패키지가 책임지는 것

| #   | 목적                      | 산출물                  | 성공 기준                                         |
| --- | ------------------------- | ----------------------- | ------------------------------------------------- |
| G1  | **브랜드 아이콘 생성**    | 24x24 SVG 아이콘 세트   | lucide 아이콘과 나란히 놓았을 때 이질감이 없을 것 |
| G2  | **다이내믹 로고/심볼**    | 파라미터화된 심볼 SVG   | 사이즈·테마·변주를 인자로 받아 재생성 가능할 것   |
| G3  | **키 비주얼 / 배경 패턴** | OG·배너·배경 SVG/PNG    | 토큰 변경만으로 전 계열 재렌더 가능할 것          |
| G4  | **재현성**                | 시드 기반 결정론적 출력 | 동일 seed → 바이트 단위 동일 SVG                  |

### 2.2. Non-Goals — 이 패키지가 책임지지 않는 것

- React 컴포넌트 구현 (→ `packages/ui`)
- 토큰 값 자체의 정의·변경 (→ `packages/tokens`, 코어 ADR)
- 사진·일러스트 등 회화적 이미지 (절차적 생성 대상 아님)
- 런타임 애니메이션 (→ 웹 프론트엔드. 여기선 정적 에셋과 좌표 데이터까지만 생산)

### 2.3. SSOT 확정 (중요)

토큰 원본이 두 곳에 존재하는 것이 확인되었다.

- ✅ **정본:** `packages/tokens/tokens/primitives.json`, `semantics.json`
  - W3C DTCG 포맷(`$value` / `$type` / `$description`), `meta.version` 보유
- ❌ **비정본:** 위키의 `00_System/design-tokens/design-tokens.json`
  - 구조가 다른 별도 사본(flat, `$value` 없음). 참조 금지

**결정: 생성기는 오직 `packages/tokens/tokens/*.json`만 읽는다.**

> **후일담.** 이 SSOT 위반은 우리 패키지만의 문제가 아니었다. `llm-wiki` 감사 결과
> 동일 사안이 이미 CEO-1013으로 식별되어 있었고, 위키의 토큰 사본은 v1.1.0에 멈춘 채
> 전 팔레트 교체(블루 → 버건디)를 놓치고 있었다. **v0.1.0의 오프브랜드 렌더링이
> 그 드리프트의 실증 사례로 CEO-1013 PR #9에 인용되었고**, 해당 사본은 삭제되었다.
> 값을 두 곳에 두면 두 곳이 갈라지며, 갈라진 것을 사람이 감지하기 전까지 문서는
> 틀린 값을 확신을 갖고 제공한다.

또한 primitive 직접 참조를 금지한 토큰 규약(`"$description": "직접 사용 금지 — Semantic 토큰을 통해 참조할 것"`)을 생성기도 동일하게 준수한다. 즉 생성기는 `semantics.json`을 우선 참조하고, semantic에 대응 항목이 없을 때만 primitive로 폴백한다.

### 2.4. 결정론(Determinism) 규약

- 모든 무작위성은 **명시적 seed**를 통해서만 도입한다. `random.seed(<int>)` 없는 난수 사용 금지.
- seed는 출력 파일명 또는 SVG 메타데이터에 기록하여 **역추적 가능**해야 한다.
- 동일 (seed, tokens version, generator version) → 동일 산출물. 이 3요소를 SVG `<metadata>`에 주석으로 심는다.

## 3. Visual Rules

### Rule A. 수면의 파문 (Ripple) — 배경 계열

- **의미:** 고요함, 깊이, 여운. 사용자가 **머무르며 읽는** 화면.
- **사용처:** 로그인, 대시보드 배경, 문서 페이지 헤더.
- **금지:** 클릭 유도가 목적인 CTA 배너에 단독 사용 금지(시선을 끌지 못함).
- **수치 규약:** _(v0.3.0에서 실측 후 개정)_
  - 동심원 3중첩, 반지름 비 `1.0 : 0.88 : 0.76`
  - 반지름 범위 **40–180px**
  - 외곽 원 `stroke-width` 0.5–2.0, 내부 링은 0.5 고정
  - opacity는 반지름 비에 비례 감쇠 (`base_opacity × ratio`), 상한 0.4
  - 색상은 semantic accent/ink/muted 계열에서만 추출

> **개정 근거 (v0.2.0 → v0.3.0)**
> 초안은 반지름 상한 400px, 비율 `1.0:0.7:0.4` 였다. 1200×630 캔버스에서 렌더한 결과
> ① 원이 캔버스 밖으로 잘려 동심원이 아닌 **정체불명의 호(arc)** 로 읽혔고,
> ② 링 간격이 지나치게 벌어져 3개가 **한 세트로 묶여 보이지 않았다.**
> 반지름을 캔버스 높이의 30% 이하로 제한하고 링 간격을 좁혀 해결했다.

### Rule B. 사선 빗줄기 (Raindrop) — 전경 계열

- **의미:** 속도감, 동적 전환, 프로모션.
- **사용처:** 프로모션 배너, 릴리즈 썸네일, 로딩 상태 배경.
- **수치 규약:**
  - **모든 빗줄기는 동일 각도.** 방향 벡터 `(dx, dy) = (0.4L, 0.9L)` → 약 24°(수직 기준). 한 캔버스 내 각도 혼용 금지.
  - 길이 L: 10–80px 범위
  - `stroke-width` 1.2 고정, opacity 0.1–0.6
  - 밀도 상한: 1200×630 기준 **180개**. 초과 시 배경 가독성 저하로 간주. (코드에서 `ValueError`로 강제)
  - **색상: accent / muted 계열만 허용. `brand.cyan` 사용 금지.**

> **개정 근거 (v0.2.0 → v0.3.0)**
> `brand.cyan (#00ffcc)` 를 빗줄기 색상 후보에 포함했으나, 웜 버건디 배경 위에서
> 네온 시안은 빗물이 아니라 **글리치/에러 표시로 읽혔다.** primitives.json의
> `"로고/에셋 전용"` 주석은 포인트 사용을 뜻하는 것으로 해석하고, 면(field) 색상에서 배제한다.
> cyan은 Rule E(심볼) 액센트로만 남긴다.

### Rule C. 타이포그래피 노이즈 (Typography Noise)

- **의미:** 빗방울이 맺힌 듯한 문학적 여운. (인터랙티브 디벨로퍼 김종민의 타이포그래피 작업 '소나기'에서 받은 영감)
- **사용처:** 타이틀 키 비주얼, 대형 히어로 텍스트. **본문·UI 라벨에는 절대 금지**(가독성/접근성 훼손).
- **수치 규약:**
  - Perlin/Simplex noise를 글자별 `dy`와 자간에 적용
  - **변위 상한: 폰트 크기의 ±4%.** 이를 넘으면 "흔들린 글자"가 아니라 "깨진 글자"가 된다.
  - 회전 적용 시 ±2° 이내
  - 원문 텍스트는 SVG `<title>`/`aria-label`로 반드시 보존 (스크린리더 대응)

### Rule D. 아이콘 그리드 엔진 (Iconography) — **G1 대응**

기존 `packages/icons`가 lucide 기반이므로, **lucide 규격과 100% 호환되는 값을 채택**한다. 그래야 자체 제작 아이콘과 lucide 아이콘을 한 화면에 섞어 써도 무너지지 않는다.

- **캔버스:** `viewBox="0 0 24 24"`
- **stroke-width:** `2` (기본), 변수로 주입 가능
- **linecap / linejoin:** `round` / `round`
- **fill:** `none`, `stroke: currentColor` (색상은 CSS가 결정 — 생성기가 색을 하드코딩하지 않는다)
- **Live area:** 24×24 중 **여백 2px**를 남긴 20×20 영역 안에 시각 요소를 배치
- **좌표 정렬:** 모든 정점은 **0.5px 그리드**에 스냅 (홀수 stroke 렌더링 시 블러 방지)
- **최소 시각 간격:** 인접한 두 stroke의 중심 간 거리 ≥ 2px (2px 두께가 서로 붙어 뭉개지는 것 방지). **동심원/동심 타원에도 동일 적용** — 반지름 차가 2px 미만이면 stroke 2px를 빼고 남는 틈이 0에 수렴해 축소 시 뭉갠다.
- **곡률:** corner radius는 stroke-width의 정수배(2px, 4px)만 허용

#### D-1. 의미 검증 (기하 검증만으로는 불충분)

기하학적 제약을 전부 통과해도 **아이콘이 의도한 의미로 읽히지 않을 수 있다.** 다음 두 항목은 자동 검증이 불가능하므로 사람이 반드시 확인한다.

- **중복 금지:** lucide에 이미 존재하는 개념을 다시 그리지 않는다. `packages/icons`는 lucide 재수출을 유지하고, 이 패키지는 **lucide가 못 채우는 브랜드 고유 모티프만** 생산한다.
- **의미 충돌 금지:** 만든 형태가 널리 통용되는 다른 기호로 읽히면 폐기한다. 아이콘만 단독으로 제3자에게 보여주고 무엇으로 보이는지 확인한다.

> **근거 (v0.3.0 시범 생성 — 3종 시도, 1종 존속)**
> Rule D 기계 검증(live area / 0.5px 스냅 / 최소 간격 / 16px 가독성)은 **모든 시도가 통과**했다.
> 그럼에도 의미 검증에서 연속 탈락했다.
>
> | 아이콘             | 형태                   | 판정                                                        |
> | ------------------ | ---------------------- | ----------------------------------------------------------- |
> | `sonagi-droplet`   | teardrop path          | lucide `droplet` 중복 → **폐기**                            |
> | `sonagi-ripple` #1 | 중첩 타원 2개          | 눈 / 녹화 버튼으로 읽힘 (lucide `eye`, `circle-dot`과 동형) |
> | `sonagi-ripple` #2 | 아래로 볼록한 호 3개   | 뒤집힌 `wifi`로 읽힘 (lucide wifi = 호 3개)                 |
> | `sonagi-ripple` #3 | 낙하점 + 호 2개        | **낙하산**으로 읽힘 → **폐기**                              |
> | `sonagi-rain`      | Rule B 각도의 사선 3개 | **존속** (약점: 맥락 부재로 기울임 슬래시로도 읽힘)         |
>
> **결론 1 — 동심 확산 형태는 의미 공간이 포화 상태다.** 24×24 / stroke 2 라는 제약 안에서
> 동심원·동심호 계열은 wifi, signal, target, eye, record, 낙하산이 이미 점유하고 있다.
> 물결 모티프가 필요하면 lucide `waves`(구불구불한 수평선, 형태가 달라 충돌 없음)를 쓴다.
>
> **결론 2 — 기하 검증과 의미 검증은 별개의 관문이다.** Rule A가 첫 렌더에서 깨진 것과
> 동일한 유형의 실패다. 수치 제약은 "잘못 만들지 않게" 막아줄 뿐 "옳게 만들어주지" 않는다.
>
> **결론 3 — 자체 아이콘은 소수 정예여야 한다.** lucide가 1000개 이상을 점유한 상태에서
> "브랜드 고유이면서 기존 기호와 충돌하지 않는" 여지는 매우 좁다. 채우려 들지 말고,
> 정말 lucide로 표현 불가능한 것만 만든다. 시도 3건 중 존속 1건(33%)이 현실적인 기대치다.

### Rule E. 다이내믹 심볼 / 로고 (Dynamic Identity) — **G2 대응**

Melbourne 방식을 따라 **불변 골격과 가변 표현을 분리**한다.

- **불변(Identity Core):** 심볼의 외곽 실루엣을 정의하는 베지어 제어점 배열. 이 좌표는 ADR 개정 없이 변경 금지.
- **가변(Expression Layer):** 내부 패턴, 색상, 미세 흔들림(wobble). 계절·테마·컨텍스트에 따라 변주 허용.
- **변주 상한:** 제어점 변위는 심볼 바운딩 박스 대각선 길이의 **±3% 이내**. 실루엣 인지성이 깨지지 않아야 한다.
- **필수 산출 변형:** `mono`(단색), `inverse`(다크 배경용), `favicon-16`(디테일 제거 단순화 버전)
- **검증:** 16px로 축소했을 때 형태가 식별되지 않으면 해당 변주는 폐기한다.

### Rule F. 세이프 존 (Safe Zone) — 구도 규칙

키 비주얼·OG 이미지는 **그 자체가 목적이 아니라 텍스트를 얹기 위한 캐리어**다. 밀도가 화면 전체에 균일하면 시선이 멈출 곳이 없고, 어디에 텍스트를 올려도 방해받는다.

- **정의:** 캔버스 중앙 **가로 62% × 세로 44%** 영역을 텍스트 예약 구역으로 둔다.
- **밀도 감쇠:** 이 영역에 위치가 잡힌 요소는 **18% 확률로만 생존**하고, 생존한 요소도 opacity에 **0.35 배율**을 곱한다.
- **적용 대상:** Rule A·B 모두. 요소의 기준점(원의 중심 / 빗줄기 시작점)으로 판정한다.
- **예외:** 텍스트를 얹지 않는 순수 패턴(타일링 배경, 텍스처)에는 적용하지 않는다.

> **도입 근거 (v0.3.0)**
> 균일 밀도 렌더 결과, 배경이 "구도"가 아닌 "노이즈"로 읽혔다. 세이프 존 도입 후
> 중앙이 비면서 자연스러운 비네트 구도가 형성되어 텍스트 배치가 가능해졌다.
> **알려진 한계:** 현재는 사각형 이진 판정이라 경계가 다소 딱딱하다.
> 거리 기반 연속 감쇠(falloff)로 개선할 여지가 있다.

## 4. 출력 규약 (Output Contract)

### 4.1. 디렉토리

```
packages/graphics-generator/
├── decisions/            # 본 ADR 등 의사결정 기록
├── src/
│   ├── tokens.py         # 토큰 로더 (DTCG $value 파싱, alias 재귀 해석, theme 인식)
│   ├── icons/grid.py     # Rule D 그리드 엔진 (실행되는 제약, 위반 시 GridViolation)
│   └── symbols/          # 로고/심볼 골격 + 변주 (미구현)
├── output/               # 생성 산출물 (git 추적 대상 아님)
├── generator.py          # 키 비주얼 생성기
└── build_icons.py        # 아이콘 세트 빌드 + 24/16px 대조 시트
```

### 4.2. 파일명

`{category}-{name}-{variant}-{seed}.{ext}`
예: `keyvisual-autumn-sonagi-og-1034.svg`, `icon-raindrop-24.svg`

### 4.3. 포맷

- **SVG가 1차 산출물이며 정본이다.** PNG는 SVG로부터 파생된 렌더 결과일 뿐이다.
- PNG 렌더는 Inkscape CLI, DPI는 용도별 고정: OG/썸네일 150dpi, 인쇄 300dpi
- `output/`은 `.gitignore` 대상. 재현 가능하므로 바이너리를 저장소에 커밋하지 않는다.
- `build_all.py`는 매 실행 시 `output/`을 **삭제 후 재생성**한다. 그러지 않으면 폐기된
  변형이나 임시 실행의 잔여물이 남아, 매니페스트에 없는데도 Storybook 정적 복사에
  섞여 배포된다. (실제로 발생하여 추가한 조치다.)

### 4.4. 매니페스트 (Storybook 연동 계약)

`build_all.py`는 산출물과 함께 `output/manifest.json`을 생성한다. Storybook 갤러리는
이 매니페스트만 읽는다.

```json
{
  "generatedAt": "...",
  "tokensVersion": "1.3.0",
  "generatorVersion": "0.3.0",
  "assets": [
    {
      "id": "...",
      "category": "keyvisual|icon",
      "name": "...",
      "path": "...",
      "theme": "dark|light|null",
      "seed": 1034,
      "width": 1200,
      "height": 630,
      "rules": ["A", "B", "F"],
      "usage": "언제 쓰는가"
    }
  ]
}
```

**갤러리를 손으로 관리하지 않는 이유:** 카탈로그를 사람이 적으면 생성기가 실제로
내보내는 것과 갈라진다. 이 저장소는 그 실패를 이미 겪었다(위키 토큰 사본, CEO-1013).
매니페스트를 유일한 입력으로 두면 **갤러리가 존재하지 않는 에셋을 광고할 수 없다.**

`usage` 필드는 선택이 아니라 필수다. "무엇을 만들 수 있는가"가 아니라 "언제 써야
하는가"를 답하지 못하면 디자인 시스템이 아니라 이미지 폴더에 불과하다.

## 5. QA 체크리스트 (에셋 승인 기준)

에셋을 `packages/ui`로 반출하기 전 아래를 통과해야 한다.

- [ ] 색상값이 코드에 하드코딩되지 않고 토큰에서 유래하는가
- [ ] seed가 기록되어 재현 가능한가

- [ ] 아이콘: 16px 축소 시 식별 가능한가

- [ ] 배경 패턴 위 텍스트 대비비가 WCAG AA(4.5:1)를 만족하는가
- [ ] 다크 테마에서도 붕괴하지 않는가

## 6. Consequences

### 긍정

- 코어 UI ADR 이력을 오염시키지 않고 그래픽 도메인 규칙을 독립 축적한다.
- `packages/icons`가 lucide 재수출에 머무르는 현 상태를 벗어날 경로가 생긴다. lucide는 유지하되, 부족한 브랜드 아이콘만 동일 규격으로 채워 넣는 **혼합 전략**이 가능해진다.
- 토큰 변경 → 전 에셋 일괄 재생성이라는 계절/테마 전환 경로가 확보된다.

### 부정 / 비용

- **규칙이 곧 품질 상한이다.** 수치 규약이 부실하면 산출물도 부실하다. 규칙 자체를 계속 개정해야 한다.
- 파이썬 파이프라인이 npm 워크스페이스 밖의 이질적 런타임으로 존재한다. CI에서 별도 취급이 필요하다.
- Rule C·E는 시각적 판단이 개입하므로 완전 자동 검증이 불가능하다. 사람의 리뷰가 남는다.

### 검증기 구현 노트 (`src/icons/grid.py`)

Rule D는 산문이 아니라 **실행되는 제약**으로 구현되어 있으며, 위반 시 `GridViolation`을 던져
SVG 출력 자체를 막는다.

- 모든 프리미티브(`Line` / `QuadCurve` / `Ellipse`)를 **폴리라인으로 평탄화**한 뒤 단일 로직으로
  최소 간격을 검사한다. 선-선, 선-곡선, 곡선-곡선, 동심원이 모두 같은 경로를 탄다.
- bounds는 선언 좌표가 아닌 **평탄화된 실제 궤적**으로 계산한다. 베지어 제어점이 캔버스 밖에
  있어도 실제 곡선이 live area 안이면 통과하며, 그 반대도 정확히 잡는다.
- **알려진 한계:** 자유형 `Path`는 곡선 평탄화 없이 검증할 수 없어, 모든 숫자 리터럴이
  0..24 범위인지만 확인하는 약한 검사에 머문다(절대 좌표 명령 필수). 가능하면 `Path` 대신
  `QuadCurve`를 쓴다.
